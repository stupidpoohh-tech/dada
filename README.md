# DADA TOWN

만든 것들이 사는 마을. 앱·문서·공간 작업물을 픽셀 마을 지도로 모아 보여주는 포트폴리오.

기획은 [PLAN.md](PLAN.md), 수록 항목은 [ITEMS.md](ITEMS.md), 에셋 명세는 [ASSETS.md](ASSETS.md).

## 로컬에서 보기

```
python3 -m http.server 8000
```

`fetch`로 `services.json`을 읽으므로 파일을 직접 열지 말고 서버로 띄워야 한다.

## 회귀 테스트

```
npm install          # 처음 한 번 (playwright)
npm test             # worker.mjs + smoke.mjs — 71초

node tests/smoke.mjs 확성기 한마디    # 그 절만 — 5~12초
```

**서버는 알아서 뜬다.** 8000번이 안 열려 있으면 검사가 저장소 루트에서 띄웠다가
끝날 때 내린다(`tools/serve.mjs`). 컨테이너가 쉬다 깨면 배경 서버가 먼저 사라지는데,
그때 화면에는 `ERR_CONNECTION_REFUSED`만 떠서 **고친 것이 깨진 줄 알고 헤매게 된다** —
이 저장소에서 검사가 실패한 이유 중 제일 잦은 것이 이거였다. 따로 띄워 둔 서버가
있으면 그것을 쓰고 건드리지 않는다(`npm run serve`도 그대로 된다).

**바꾼 곳만 돌릴 수 있다.** 절 이름 조각을 인자로 주면 그 절만 돈다. 한 줄 고칠
때마다 71초를 물리면 고치는 시간보다 기다리는 시간이 길어진다. 다만 **푸시 전에는
인자 없이 한 번 돌린다** — 부분만 돌고 넘어가면 남의 절을 깨뜨린 것을 못 본다
(건너뛴 절이 있으면 마지막 줄이 그렇다고 말해 준다).

두 벌이다. `tests/worker.mjs`는 **브라우저도 wrangler도 없이** `worker.js`를 모듈로
그대로 불러 `fetch()`를 부른다(KV는 `Map` 하나로 흉내 낸다) — 서버가 있어도 검사는
여전히 `npm install` 한 번이면 돈다. `npm run test:worker` / `test:browser`로 따로도 돈다.

`tests/smoke.mjs`의 검사는 **전부 실제로 한 번씩 깨졌던 것**이다. 커버리지를 채우려고
만든 게 아니라 "또 이럴까 봐" 남긴 목록이니, 새 버그를 잡으면 여기에 한 줄 더한다.
지금 지키고 있는 것 — 두 책이 서로의 설정을 물고 오지 않기, 목록 카드가 빈 해시를 물지 않기,
캐릭터 판정이 흔들리지 않고 64px을 넘기, 여닫고 호버한 뒤에도 마을이 한 박자이기,
터치에서 건물이 얼어붙지 않기, 안내가 닫은 뒤 돌아오고 대비가 AA를 넘기,
책이 건물에서 출발해 끊김 없이 날아오기, 화면과 `list.html`이 `services.json`과 어긋나지 않기.

## 찍어 보기 (`tools/shot.mjs`)

고친 것이 눈에 어떻게 보이는지 확인할 때 쓴다. **매번 스크립트를 새로 쓰지 않기
위해 있는 파일이다** — 그때마다 다시 쓰면 매번 같은 데서 걸린다(크롬 경로, 서버가
떠 있는지, 애니메이션이 매번 다른 자리에서 잡히는지).

```bash
node tools/shot.mjs                           # 폰·데스크톱 두 장
node tools/shot.mjs --phone --map             # 폰의 지도만
node tools/shot.mjs --crop 72,68,100,100      # 지도의 그 %구역만 (세모집 마당)
node tools/shot.mjs --click '#sayHi'          # 누른 뒤에 찍는다
node tools/shot.mjs --grid --crop 33,0,69,40  # %눈금을 얹어 찍는다 (좌표 잴 때)
```

세 가지를 여기서 한 번에 처리한다.

- **서버를 알아서 띄운다** (`tools/serve.mjs` — 검사와 함께 쓴다)
- **움직임을 0에 세운다.** 마을은 늘 숨쉬고 흔들려서, 세우지 않으면 찍을 때마다 건물
  크기가 미세하게 달라 「고치기 전후」를 견줄 수가 없다
- **크롬 경로를 안다** (`/opt/pw-browsers/chromium`). 그냥 `chromium.launch()`를 부르면
  `Executable doesn't exist`로 죽는다

`--grid`는 **재는 도구라 늘 큰 화면(1600×1400)으로 찍는다.** 폰 해상도에서는 1%가
3px밖에 안 돼 눈금이 뭉개지는데, 재려고 얹은 것이 못 읽히면 얹은 뜻이 없다.
숫자는 크롭 안쪽에 붙는다 — 지도 꼭대기에 두면 잘라낸 그림 밖으로 나간다.

## 작업물 전체 목록 (`/list.html`)

**마을은 JS로 그려지므로 크롤러와 스크린리더에게는 빈 페이지다.** 실제로 재보면 JS를 끈
`index.html`의 본문은 74자이고 항목 이름이 하나도 없다 — 검색으로 이 사이트에 닿을 길이 없다는 뜻이다.
링크드인 대체를 노리는 사이트에서 이건 치명적이라, 같은 데이터를 **HTML에 그대로 박은**
정적 페이지를 하나 둔다 (같은 조건에서 1,200자, 항목 이름·설명·약력·연락처가 전부 읽힌다).

**마을은 경험, `/list`는 정보.** 예쁠 필요 없고 읽히면 된다.

```
python3 tools/build_list.py
```

`services.json`을 고칠 때마다 함께 돌린다. 빌드 과정이 없는 사이트라 손으로 돌리는 대신,
**`npm test`가 어긋남을 잡는다** — 어느 항목이 빠졌는지와 이 명령을 다시 돌리라는 안내까지 나온다.
`sitemap.xml`·`robots.txt`도 같이 만들어지고, 목록 모달 하단에서 이 페이지로 가는 링크가 붙는다.

## 편집용 원본

**저장소 루트가 그대로 게시되므로, 배포에 쓰지 않는 파일은 저장소에 두지 않는다.**
URL만 알면 누구나 받아갈 수 있기 때문이다. 아래 둘은 `.gitignore`에 있다.

- `assets/map/town.jpg` — 원본 지도 (`tools/cut_sprites.py`가 `town-web.jpg`를 만들 때 쓴다)
- `assets/sprites/*.png` — 스프라이트 원본 시트 (`cut/` 안의 잘라낸 것만 배포한다)

`86bfa0a` 이전 커밋에는 들어 있으므로 필요하면 이렇게 꺼낸다.

```
git show 86bfa0a:assets/map/town.jpg > assets/map/town.jpg
```

**저장소 루트에 남아 있는 원본이 넷 있다** — 다원님이 GitHub 웹으로 올리는 자리가
거기라서다. 이것들은 지우지 않고 `.assetsignore`로 **배포에서만 뺀다**. 지우면 다시 뜰
때 원본부터 다시 받아야 해서다.

| 파일 | 무엇을 뜨나 | 뜨는 도구 |
|---|---|---|
| `me-front.png` | 다원 앞모습 `me.png` | `tools/cut_me.py` |
| `me-back.png` | 다원 뒷모습 `me-back.png` | `tools/cut_me_back.py` |
| `sign.png` | 마을 나가는 길 표지판 | `tools/cut_sign.py` |
| `town-background.png` | 건물 시트를 뜰 때 쓰는 바탕 | `tools/cut_buildings.py` |

`.assetsignore`에 적을 때 **앞에 슬래시를 반드시 붙인다**(`/me-front.png`). 안 붙이면
gitignore 규칙상 어느 깊이에서나 걸려서, 이름이 같은 `assets/sprites/cut/me-front.png`
쪽까지 함께 빠진다 — **배포에서만 그림이 사라져** 알아채기 어렵다. 실제로 밟은 적이 있다.

## 항목 추가하기

`services.json`의 `items`에 한 덩어리를 넣고 **`python3 tools/build_list.py`를 돌린다.**
설명에 줄바꿈(`\n`)을 넣으면 카드에서도 `/list`에서도 줄이 나뉜다.
지도 팝오버와 목록 모달은 JSON을 직접 읽으므로 자동으로 바뀌지만, `list.html`은 생성물이라
다시 만들어야 한다. 잊어도 `npm test`가 어느 항목이 빠졌는지 짚어준다.

```json
{
  "id": "english-learn",
  "name": "고등영어 학습웹",
  "district": "school",
  "type": "app",
  "url": "https://dada-learn.pages.dev/",
  "description": "문법, 리스닝, 패턴까지 3가지 학습도구",
  "date": "2026-06",
  "icon": "📚",
  "status": "live"
}
```

- `district` — `museum · school · seonggyungwan · park · company · cafe · bank · house · me`
- `type` — `app`(새 탭) · `doc`(내부 페이지) · `video` · `external`
- `date` — **만든 시기 `YYYY-MM`. 빠뜨리면 `npm test`가 잡는다.**
  **목록 모달은 최근 만든 것부터 늘어놓는다** — 이 값으로 정렬하고 달 단위로 묶는다.
  카드 위 작은 연월도 같은 값이다. 구역별 묶음은 `/list.html`에만 있다 (구역은 지도가 한다).
  화면에는 `26.05`로 짧게 나오지만 정렬을 위해 데이터는 네 자리 연도로 둔다
- `group` — 한 구역 안에서 소제목으로 나눌 때. 나눌 게 없으면 안 쓴다
- `status` — `live` · `beta` · `demo`
- `featured` — 「⭐ 추천 픽」에 올릴 것. **숫자가 곧 순서다**(1이 맨 위).
  `items` 배열 순서를 따르지 않는 이유는, 그 배열이 구역별로 묶여 있어
  **무엇을 먼저 보여줄지와 아무 상관이 없기 때문**이다 — 순서를 바꾸려고 항목을
  옮기면 목록·`/list.html`의 묶음까지 같이 흐트러진다. 안 쓰면 추천에 안 올라간다
- **설명은 만든 사람이 직접 쓴다.** 방문자가 그 작업물에 대해 읽는 유일한 문장이라
  그럴듯하게 지어낸 문장을 두면 신뢰가 깎인다. 두세 문장까지 괜찮다

## 움직임(애니메이션)

건물·사람들·캐릭터·까마귀·쪽지·확성기는 항상 움직인다 (사용자 결정으로 OS '동작 줄이기'와
무관하게 상시 재생).
**애니메이션은 모두 `transform` 축약형으로 쓴다.** `scale:` / `translate:` 개별 CSS 속성은
카카오톡 인앱 브라우저 같은 구형 웹뷰에서 무시되어 애니메이션이 통째로 멈춘다.
같은 이유로 좌우 반전·물결처럼 여러 변형이 겹치는 곳은 요소를 나눠 각자 transform을 갖게 한다.

### 지나가기만 하는 것은 두지 않는다

한때 구름 셋이 하늘을 가로지르고, 새 둘이 사선으로 활강하고, 자동차 셋이 도로를 돌았다
(`CLOUDS` · `BIRDS` · `CAR_ROUTES`). 그때는 마을에 움직이는 것이 그것뿐이라 살아 있어
보였는데, 그 뒤로 까마귀·쪽지·확성기가 차례로 들어오면서 **눈이 쉴 자리가 없어졌다.**
2026-08에 셋을 전부 걷어냈다 — 하나씩이 나빠서가 아니라 합쳐 놓으니 번잡해서다.

남은 움직임은 전부 **뜻이 있는 것**이다. 건물은 눌러볼 수 있다는 신호로 숨쉬고, 사람들은
공원이 사람들 구역이라 들썩이고, 까마귀·쪽지·확성기는 저마다 문이다. 그래서 이제
**마을에서 움직이는 것은 곧 눌러볼 것**이라는 규칙이 성립한다.

잔디에 앉은 새 둘(`PERCHED`)은 남겼다 — 걷어낸 것은 「새」가 아니라 「가로지르는 움직임」이라,
움직이지 않는 그림은 지도에 그려진 꽃·벤치와 같은 자리에 있다.

자동차가 사라지면서 `canopy`(차가 나무 뒤로 지나가도록 나무만 오려 덮던 레이어)와
`.sky` · `.road` 레이어도 함께 걷었다 — 가릴 것이 없으면 지도를 한 장 더 까는 값만 남는다.
쓰지 않게 된 그림(구름·자동차·나는 새·안 쓰는 사람 다섯)은 **지우지 않고 `.assetsignore`에
적어** 배포에서만 뺐다. 원본 시트가 `.gitignore`에 있어서 지워 버리면 되돌릴 때 시트부터
다시 받아야 하기 때문이다.

### 건물은 같이 숨쉬고, 개별 요소는 저마다 다른 걸음을 갖는다

움직임의 규칙이다. 건물 여덟은 전부 같은 `bldg-idle`로 함께 부푼다 — 하나만 다른 리듬을
주면 마을이 어수선해 보인다. 대신 **하나짜리 물건들은 서로 다르게 움직인다.**

| 무엇 | 걸음 | 박자 |
|---|---|---|
| 건물 여덟 | 두 번 숨쉬듯 부푼다 | 2.4초 (다 같이) |
| 공원 사람들 | **왼쪽부터 오른쪽까지 파도타기** | 2.4초 · 0.19초씩 늦게 |
| 우편함 | **좌우로 인사하듯 또잉또잉** | 2.4초 |
| 마당의 확성기 | **한 박자에 두 번 앞으로 내지른다** | 2.4초 |
| 까마귀 Croww | 퍼덕이고 갸웃한다 | 2.4초 |
| "나" 캐릭터 | 손 흔들며 폴짝 | 2.4초 |
| 날아다니는 쪽지 | 파장처럼 뽀잉 · 펄럭 | **1초 · 0.55초** |

박자(2.4초)를 공유하되 그 안에서 하는 일이 달라야 **같은 것으로 안 읽힌다.**
쪽지만 박자까지 다른데, 마을의 일부가 아니라 **마을 위에 온 것**이라서다.

**우편함이 기울 때 크기를 함께 키우는 것**(`scale(1.34, 1.14)`)은 지도를 오려낸 복제본이던
시절의 값이다. 그때는 제자리에서 벗어나면 뒤의 원본 우편함이 드러나 이중으로 보여서
회전으로 밀려나는 만큼(높이 × sin7°) 가로로 덮어야 했다. 지금은 따로 오려낸 그림이라
그럴 이유가 없지만, 커졌다 작아지는 폭이 「또잉또잉」의 몸짓 자체가 돼 그대로 둔다.

**공원 파도가 §9에서 걷어낸 그 파도와 다른 이유.** 그때 걷어낸 것은 **마을 전체**를
파도로 만든 것이었다 — 건물이 눌린다는 말을 하려던 표식이었고, 그건 결국
「무엇이 눌리는지」를 말해주지 못했다. 이건 한 무리가 함께 노는 장면이라 다른 이야기다.

**여기에 표식을 더 얹지 않는다.** 폰에서 뾰잉은 건물 5.1px·우편함 0.2px뿐이라 눈에 안
띈다는 지적은 맞지만, 해결책을 두 번 만들어 보고 두 번 다 걷어냈다 — 줄마다 위상을
어긋낸 위→아래 파도(움직임이 흘러도 「무엇이 눌리는지」는 여전히 안 말해준다)와,
문마다 하나씩 띄운 핫핑크 화살표(가리키기는 확실하지만 열 개가 붙으면 마을이 아니라
표지판이 된다). 눌러볼 수 있다는 말은 지도 아래 `.hint` 한 줄이 맡는다.

**지도 아래 안내(`.hint`)는 아무것도 열려 있지 않을 때만 보인다.** 눌러볼 수 있다는 걸
알려주는 유일한 글이라 한 번 사라지고 끝이면 안 된다 — 예전에는 처음 무언가를 열면
`gone`이 붙은 채 영영 돌아오지 않았다. 열고 닫는 모든 곳(구역 패널·책·목록 모달)에서
`syncHint()`를 불러 지금 상태에 맞춘다. 숨길 때는 `display`가 아니라 `visibility`를 써서
아래 것들이 들썩이지 않게 한다.

**눈에 띄게 하려고 흐린 색을 깜빡이면 안 된다.** `--faint`(2.68:1)에 숨쉬기를 얹었더니
최저점에서 1.64:1까지 떨어져 오히려 안 읽혔다. 색을 `--sub`(5.49:1)로 올리는 편이
훨씬 잘 보인다. 숨쉬기는 WCAG AA(4.5:1)를 깨지 않는 폭(.92~1)으로만 남겼고,
`npm test`가 이 최저점을 지킨다.

**호버·뾰옹이 물러난 뒤에는 반드시 `resyncIdle()`을 불러야 한다.** 잠깐 다른 애니메이션이
얹혔다 사라지면 idle이 0부터 다시 시작해 **그 요소만** 마을과 어긋난다 — 재보면 2.4초 주기에서
2~3초씩 벌어져 사실상 반대 위상이 된다. 그래서 팝오버를 닫을 때·호버가 풀릴 때 다시 맞춘다.

**이때 전부 0으로 되돌리면 안 된다.** `syncIdle()`처럼 모두에게 지금 시각을 넣으면 어긋남은
없어져도 **온 마을이 그 순간 한 번 움찔한다.** `resyncIdle()`은 가장 많은 요소가 쓰고 있는
`startTime`(= 마을이 이미 타고 있는 박자)을 찾아 **뒤늦게 합류한 것만** 거기에 끌어다 붙인다.
`syncIdle()`은 처음 한 번만 쓴다.

**터치 기기에서는 `:hover`가 탭한 뒤에도 눌린 채 남는다.** `.spot:hover .pop`의 `animation: none`
때문에 그 건물만 통째로 얼어붙었다가, 나중에 hover가 풀릴 때 0부터 다시 시작한다. 그래서
호버 규칙은 `@media (hover: hover)`로 마우스가 있는 기기에만 건다 (`:focus-visible` 쪽은 그대로 둔다).

**"나" 캐릭터는 버튼이 아니라 안쪽 `.me-figure`가 움직인다.** 버튼이 흔들리면 누를 자리도
같이 흔들려 조준이 안 된다. 캐릭터는 지도 폭의 5.4%뿐이라 폰에서 20px 남짓인데 위아래로
7px씩 뛰기까지 하면 맞히기 어렵다. 그래서 버튼은 가만히 두고, `::after`로 최소 64px짜리
판정 영역을 그림보다 넓게 깐다 (터치 기준 44px). 이때 `me-idle`·`hop` 키프레임에는
자리 이동(`translate`)을 넣지 않는다 — 그건 버튼이 맡는다.

## 건물이 상시로 뾰잉거리는 원리

각 구역의 `.pop`은 **지도와 별개로 오려낸 건물 그림**이다(`assets/sprites/buildings.png` →
`tools/cut_buildings.py` → `assets/sprites/cut/building-<id>.webp`). 배경 지도
(`town-web.jpg`)는 처음부터 건물 없이 그려져 있고, 그 빈 자리 위에 이 그림을 얹는 것뿐이라
지도 픽셀과 맞춰 자르거나 마스크로 실루엣을 덜어낼 필요가 없다. 2.4초에 두 번, 위로
늘었다가 옆으로 퍼진다. 호버·열린 상태에서는 더 크게 튄다.

좌표는 "나"·확성기·까마귀와 같은 **밑변 기준**이다(`building: { src, at, w }`) — `at`이
건물이 땅에 닿는 자리(지도 %), `w`가 지도 폭 기준 그림 폭이고 높이는 원본 비율대로
저절로 정해진다. 다만 건물은 구역 버튼(`.spot`) 안에 딸린 것이라, 구역 상자(`rect`)
기준 **상대 좌표로 한 번 환산해** 심는다 — `%`끼리의 비율이라 창 크기가 바뀌어도
어긋나지 않고, 지도 픽셀을 다시 재는 코드(예전의 `syncPops()`)가 아예 필요 없다.

**밑변은 `bottom`으로 못 박는다 — `top` + `translateY(-100%)`이 아니다.** 이건
폰에서 마을이 통째로 무너진 적이 있는 자리다. 스프라이트의 `<img>`에는 `width`·`height`
속성이 없어 **그림이 도착하기 전에는 비율을 모르고, 그래서 상자 높이가 0이다.** 그동안
`-100%`도 0이라 건물·까마귀·확성기가 전부 「제 키만큼 아래」에 그려지는데, 크롬은 그림이
온 뒤 퍼센트 변환을 다시 계산해 제자리로 돌려놓지만 **iOS 사파리는 그러지 않는다.**
그래서 폰에서만 마을이 흘러내렸고, 키가 가장 큰 세모집은 지도 밖으로 잘려 나갔다
(가로는 `-50%`가 인라인 `width`에 걸려 멀쩡했다 — **세로만** 어긋난 이유가 이것이다).

`bottom`은 담는 상자의 높이에 걸리므로 자기 높이를 몰라도 된다. 밑변이 먼저 못 박히고
그림은 그 위로 자란다. 데이터의 밑변 좌표를 CSS 값으로 바꾸는 곳은 `app.js`의 `upTo`
한 군데뿐이고, 건물·"나"·확성기·까마귀·우편함·공원 사람들이 전부 이걸 쓴다.
가운데를 잡는 쪽지(`.note-spot`)만 예외인데 — 날아다니는 것이라 발밑이 없다 —
거기는 CSS에 `aspect-ratio`를 박아 그림을 기다리지 않고도 높이가 서게 했다.

### 크기는 빈 터에 맞춘다

**옛 지도의 건물 상자를 그대로 옮겨 쓰면 안 된다.** 그 상자는 마스크로 실루엣을 도려낼
것을 전제한 **여백 있는 상자**였는데 새 그림은 알파에 딱 맞춰 잘린 것이라, 같은 `w`를
주면 건물이 1할 남짓 커진다. 게다가 새 배경은 다시 그려진 것이라 나무·울타리 자리가
옛 지도와 달라 **빈 터 자체가 좁아진 곳이 있다**(학교가 그렇다).

그래서 좌표는 배경에서 직접 잰다. 열린 잔디는 매끈하고 울타리·나무는 오돌토돌하니
국소 표준편차로 가른 뒤, 꽃·풀포기가 낸 구멍을 닫힘 연산으로 메우고, **그 안에 건물
그림의 비율 그대로 들어가는 가장 큰 직사각형**을 찾는다(넓이만 큰 직사각형을 찾으면
모양이 안 맞는다 — 세모집 자리는 262×54 띠가 나왔다). 자리는 현관 앞 돌길 쪽으로
당겨 문이 길과 이어지게 한다.

### 채도를 낮춰서 얹는다

건물이 배경에 박혀 있던 시절에는 둘이 한 그림에서 나와 색이 저절로 어울렸다. 지금은
따로 그려진 그림이라 그대로 얹으면 빨간 지붕·파란 지붕·차양이 배경의 순한 초록 위에서
쨍하게 도드라진다. 옛 지도 건물의 채도를 재서 견주니 새 그림이 **1.34배** 높았고,
`tools/cut_buildings.py`의 `SATURATION = 0.75`가 그 차이를 되돌린다(실측 0.745).
색상과 밝기는 건드리지 않고 채도만 준다 — 자세한 계산은 그 파일의 `desaturate()`에 있다.

건물과 사람들은 같은 2.4초 박자로 함께 움직인다. 각각 다른 시점에 만들어져 수십 ms 어긋나므로
`syncIdle()`이 `startTime`을 맞춰준다 — 박자가 어긋나면 눈에 거슬린다.
이때 **기준값은 `document.timeline.currentTime`이어야 한다.** 다른 애니메이션의 `startTime`을
베끼면 아직 시작 전이라 `null`일 수 있고, `null`을 넣으면 전부 멈춘다.

## 세모집 마당의 확성기

집 테마송이 나오는 자리다. `speaker.song`이 있으면 **진짜 버튼**이라 누르면 재생되고
가사 팝업이 뜨고, 없으면 까마귀와 같은 규칙으로 **누를 수 없는 풍경**으로만 선다 —
없는 것을 가리키는 문은 만들지 않는다.

```json
"speaker": {
  "name": "집 테마송 확성기",
  "at": [83.8, 82.9],       // 받침이 지붕에 닿는 자리 (지도 %)
  "w": 3.08,                // 지도 폭 기준 %. 처음 크기(4.4)의 70%로 줄였다
  "sprite": "horn.png",
  "song": {
    "title": "집이 어떻게 세모",
    "audio": "assets/audio/house-theme.mp3",
    "lyrics": [
      { "label": "Intro", "lines": ["우리 집은 세모네, 예."] },
      { "label": "Verse 1", "lines": ["사람들은 내게 말하지.", "…"] }
    ]
  }
}
```

**걸음은 반동이다** — 한 박자에 두 번 앞으로 내질렀다 돌아온다. 회전(우편함)도
뜀(캐릭터)도 파도(사람들)도 이미 쓰였고, 무엇보다 **소리를 내는 물건이니 앞으로
밀리는 게 제 몸짓**이다. 축은 잔디에 닿은 받침(`transform-origin: 34% 92%`)이고,
나팔이 오른쪽을 보므로 내지르는 방향도 오른쪽이다. **재생 중에는 같은 반동을 더
크고 빠르게**(`horn-playing` → `horn-shout` .6초) 갈아 끼워, 소리가 나고 있다는 것이
눈에도 보이게 한다. `horn-shout`는 마을의 idle 박자(`IDLE_ANIMS`)에는 안 든다 —
재생은 상시 리듬이 아니라 방문자가 시작한 독립된 사건이라서다.

세모집 옆에 서 있지만 **세모집 클릭을 가로채지 않는다.** 각자 판정 영역이 따로다 —
회귀 테스트가 확성기를 누른 뒤에도 세모집을 누르면 카탈로그가 열리는지 함께 지킨다.

### 누르면 — 재생 + 가사

`<audio controls>`를 그대로 쓴다. 재생·일시정지·탐색·볼륨 바를 새로 만들지 않는
이유는 브라우저 내장 컨트롤이 이미 키보드·스크린리더 접근성을 갖추고 있어서다 —
새로 만들면 그걸 다시 흉내 내는 셈이 된다.

**자동재생은 페이지 로드에 걸지 않는다.** 브라우저가 막기도 하지만, 그보다 먼저
소리가 방문자 허락 없이 나는 건 무례하다. 재생은 **누르는 손 안에서만** 시작된다
(`audio.play()`를 클릭 핸들러 안에서 바로 부른다 — 사용자 동작 안이라 정책에 안 걸린다).

가사는 절 단위 배열이다. 절마다 `label`(자막처럼 작게)과 `lines`(한 줄씩)를 두고,
JS가 그대로 단락으로 그린다 — 마크업 없이 텍스트만 바꾸면 된다.

**다른 패널을 열면 조용히 멈춘다.** 구역을 새로 누르거나, 쪽지 묶음을 열거나,
Escape를 누르거나 — 전부 `closePanel()` 한곳을 거치므로 거기 `stopSong()` 하나만
있으면 된다. 확성기를 다시 누르면(토글) 그 자리에서도 멈춘다.

### 파일

원본 mp3는 편집 원본이 아니라 **그 자체가 배포되는 최종 자산**이라 스프라이트
시트와 달리 `.gitignore`에 넣지 않는다 — `assets/audio/house-theme.mp3`에 그대로
커밋돼 있다. ffmpeg 없이는 이 저장소에서 재인코딩할 수 없으므로, 받은 파일을 이름만
바꿔 그대로 쓴다. 곡을 바꾸려면 같은 경로에 파일을 갈아 끼우고 `services.json`의
`song.title`·`lyrics`만 고치면 된다 — 코드는 안 건드린다.

### 스프라이트

한 장짜리라 프레임 맞춤이 필요 없어 `cut_sprites.py`가 자른다
(여러 장을 포개야 하는 까마귀·쪽지만 `cut_crow.py`·`cut_note.py`로 따로 나가 있다).

```
python3 tools/cut_sprites.py horn     # 시트 하나만 자를 수도 있다
```

## PC에서는 스크롤이 없다

지도 높이를 **`100dvh`에서 나머지 요소들의 높이(336px)를 뺀 만큼**으로 묶어,
마을 · 안내 · 버튼 · 푸터가 한 화면에 다 들어온다 (`styles.css`의 `.map-holder`).

```
336 = 상단 118 + 지도 아래 여백 14 + 안내 22 + 13 + 버튼 44 + 34 + 푸터 90
```

예전에는 이 값을 290px로 잡아 두어 **어느 화면에서나 딱 45px씩 넘쳤다** —
1280·1440·1920 어디서 봐도 스크롤바가 하나 생기던 이유가 그것이었다.
**지도 아래 요소의 높이를 바꾸면 이 숫자도 같이 고쳐야 한다.**
모바일은 해당 없다 — 거기서는 지도 아래로 패널이 흐름대로 붙으므로 스크롤이 정상이다.

## 지도 레이어 순서

확성기(3) < 우편함(4) < "나"(5) < 쪽지(7) < 투어 그늘(8) < 투어 테두리(9) 순으로 얹힌다 —
문은 가려지면 안 되고, 그 위를 덮을 수 있는 것은 투어의 그늘뿐이다. `.map`에
`isolation: isolate`를 줘 이 z-index가 지도 밖(구역 패널·아트북 팝업)까지 넘치지 않게
가둔다. 그늘이 **화면이 아니라 지도만** 어둡게 하는 것도 이 `.map`의 `overflow: hidden`
덕이다 (아래 「첫 방문 안내」).

지도 **밖**의 겹은 따로다 — 추천 픽(45·46) < 책 팝업(50) < 안내 덮개(55) <
다원·말풍선·투어 카드(56) < 목록·한마디 모달(60). 모달이 안내보다 위인 것은 일부러다.

## 구역 위치 조정하기

주소 뒤에 `?tune`을 붙이면 구역 영역이 붉게 표시되고, 지도를 클릭하면 좌측 하단에 좌표가 뜬다.
그 값을 `services.json`의 `districts[].rect`(`[left, top, width, height]`, 단위 %)나
`character`(`[x, y]`)에 넣으면 된다.

## 넘겨보는 책 뷰어

별도 페이지가 아니라 **지도와 똑같은 크기의 팝업**으로 지도 위에 얹힌다(`.book-overlay`).
좁은 화면에서는 지도 크기로는 책이 너무 작아지므로 화면 전체를 쓴다.

**뷰어 한 벌을 여러 권이 나눠 쓴다.** 책마다 다른 것은 폴더·쪽수·해시뿐이고 제목은 항목 이름을 그대로 쓴다.
항목에 `"open": "book"`과 `book` 덩어리를 두면 등록된다.

책은 그 구역 건물에서 날아온다.

**우편함은 구역과 별개의 문이다** (`districts[].mailbox: { sprite, at, w, item }`).
세모집 건물은 소개서를 바로 열고(`direct`), 마당의 우편함은 게임 안내서(`/game/`)를
연다 — 누르면 겉장(`item.cover`)이 우편함에서 화면 가득 날아오른 뒤 그 그림 그대로
페이지가 열린다(`?from=town`이면 목차 대신 표지에서 시작). 우편함도 건물과 같이 따로
오려낸 그림이라(`assets/sprites/mailbox.png` → `tools/cut_buildings.py` →
`mailbox.webp`) 밑변 기준 좌표(`at`/`w`)를 쓴다 — "나"·확성기와 같은 방식이다.
우편함은 `<a>`라 JS가 없어도 동작하고, 링크 상자는 가만히 있고 안의 `.mbox` 그림만
움직인다("나" 캐릭터와 같은 규칙 — 판정 영역은 `::after`로 44px 이상). 마을과 같은
2.4초 박자(`mbox-idle`, `IDLE_ANIMS`에 포함)로 뛰되, 건물이 두 번 숨쉴 때 **한 번만
크게 흔들어** 건물과 다른 요소로 읽힌다.

```json
"open": "book",
"book": { "dir": "assets/portfolio/house/", "pages": 6, "hash": "house",
          "ratio": "449 / 635", "flat": true }
```

이미지는 `dir` 아래 `p01.jpg`(본문)와 `t01.jpg`(썸네일) 규칙으로 찾는다.
해시는 `#art` · `#art-5`처럼 쪽번호가 뒤에 붙고, 등록되지 않은 해시는 무시한다.

**`ratio`는 페이지 비율이고 책과 썸네일이 함께 쓴다.** JS가 `#bookOverlay`에 `--ratio`로 얹는다 —
책(`#bk`)과 썸네일 줄(`#bkStrip`)이 형제라 둘의 공통 조상에 넣어야 같이 받는다.

**세로로 긴 책은 넓은 화면에서도 화면 전체를 쓴다.** 지도가 가로형이라 세로 페이지를 그 안에
가두면 높이가 모자라 글씨가 작아진다. `ratio`의 세로가 가로보다 크면 JS가 `.full`을 붙인다.

**`"flat": true`면 책이 아니라 브로슈어로 그린다** — 종이 두께와 책등 그늘이 빠진다.
세로 페이지는 가로 컨테이너 안에서 가운데 놓이므로, 컨테이너 가장자리에 붙는 두께 장식이
페이지에서 멀리 떨어져 허공에 뜬 선으로 보인다. 아트북(가로)은 두께를 그대로 쓴다.

**책은 그리기 전에 등록해야 한다.** 목록 카드가 책 해시를 `href`로 쓰기 때문에,
`init()`에서 `renderModalList()`·`initPicks()`보다 먼저 `books`를 채운다.
순서가 뒤집히면 카드가 `#`만 물고 렌더되어 클릭해도 아무 일도 안 일어난다.

미술관·세모집처럼 항목이 하나뿐인 구역은 팝오버를 거치지 않고 바로 책이 열린다 —
`districts[].direct`에 항목 id를 적으면 그 구역이 그렇게 동작한다.

**책은 누른 건물에서 날아온다** (`flyBook()`). 어디서 왔는지가 보여야 장식이 아니라 설명이 된다 —
세모집을 눌렀으니 그 집에서 카탈로그를 꺼내온 것처럼 보인다. 출발점은 `book.district`로 찾은
그 구역 버튼이고, 닫으면 같은 자리로 되돌아간다(닫는 쪽이 더 짧다 — 여닫기를 반복하는 물건이라
길면 두 번째부터 거슬린다).

날아오는 느낌이 나려면 세 가지가 필요하다. 하나라도 빠지면 그냥 커지는 것처럼만 보인다.

- **가는 동안 보여야 한다.** `opacity: 0`에서 시작하면 여정의 앞부분이 통째로 안 보인다.
  밝아지는 건 첫 90ms에 따로 끝내고, 이동하는 480ms 내내 불투명하게 둔다.
- **그림이 준비된 뒤에 날려야 한다.** 큰 페이지를 처음 그리느라 프레임이 100ms 넘게 멈추면
  비행 구간이 통째로 먹힌다. 첫 장을 한가할 때 미리 `decode()`해 두고, 그래도 준비가 안 됐으면
  준비될 때까지(최대 400ms) 기다렸다 연다.
- **종이 한 장만 날아야 한다.** 컨테이너의 검은 판까지 같이 기울면 기운 검은 슬래브가 보인다
  (`.book.flat .leaf`의 배경을 지우고 그림자를 그림에 건다).
- **어두운 바탕이 출발지를 가리면 안 된다.** 이게 가장 크다. 팝업째로 페이드하면
  ① 날아오는 책까지 같이 흐려지고 ② 0.18초 만에 새까매져 **출발한 집이 안 보인다** —
  검은 화면에서 그냥 나타나는 것처럼 읽힌다. 그래서 어두운 바탕은 `.book-overlay::before`가
  따로 맡고, `veil-in`의 앞 4분의 1은 거의 투명하게 버틴다. 그 동안 지도와 집이 보여야
  "저 집에서 나왔다"가 성립한다. 위아래 UI도 책보다 늦게 스며든다.

**재기 전에 이전 애니메이션을 먼저 걷어내야 한다.** 닫을 때 쓴 변형이 `fill`로 남아 있으면
`getBoundingClientRect()`가 그 변형이 적용된 좌표를 줘서 출발점이 엉뚱한 곳이 된다
(`syncPops()`가 뾰잉을 잠깐 끄고 재는 것과 같은 함정).

넘어가는 장이 책등을 축으로 3D 회전하고(`backface-visibility: hidden`으로 뒷면이 보이면 사라진다),
좌우에 종이 두께를 쌓아 읽은 만큼 왼쪽이 두꺼워진다.
방향키·좌우 클릭·스와이프·하단 썸네일로 이동하고, `#art` / `#art-5` 해시로 특정 쪽을 공유할 수 있다.
원본 PDF는 배포하지 않는다.

페이지를 다시 뽑으려면 — **긴 변을 2000px에 맞춘다.** 가로 페이지든 세로 페이지든
화면에서 차지하는 크기가 비슷해지고, 세로 페이지를 폭 기준으로 뽑으면 쓸데없이 커진다.

```
pip install pymupdf pillow
python3 -c "
import pymupdf, io
from PIL import Image
DIR, LONG = 'assets/portfolio/house/', 2000
d = pymupdf.open('원본.pdf')
for i, p in enumerate(d):
    z = LONG / max(p.rect.width, p.rect.height)
    pix = p.get_pixmap(matrix=pymupdf.Matrix(z, z))
    im = Image.open(io.BytesIO(pix.tobytes('png'))).convert('RGB')
    im.save(f'{DIR}p{i+1:02d}.jpg', quality=82, optimize=True, progressive=True)
    im.resize((260, round(260*im.height/im.width))).save(f'{DIR}t{i+1:02d}.jpg', quality=75)
"
```

쪽수나 비율이 바뀌면 `services.json`의 `book.pages`·`book.ratio`를 함께 고친다.
**한 장만 갈아끼울 때는 그 파일 두 개(`pNN.jpg`·`tNN.jpg`)만 덮어쓰면 된다** — 나머지는 안 건드려도 된다.

## 방문 통계

**이 마을은 URL이 바뀌지 않는다.** 구역을 열어도, 책을 넘겨도, 목록을 열어도 주소는
`/` 그대로다. 그래서 자동으로 세어지는 페이지뷰 하나로는 **"몇 명이 왔다"까지만** 알고
"무엇을 봤는가"는 한 줄도 안 남는다. 그건 커스텀 이벤트로 각자 자리에서 보낸다.

### 갈아 끼우는 자리는 `ga.js` 위쪽 두 줄뿐이다

```js
var ID = 'G-62X7QQW0GM';   // GA4 측정 ID
var CF_TOKEN = '';         // Cloudflare Web Analytics 토큰 (아래)
```

**GA4는 켜져 있다.** 측정 ID를 새로 받아야 할 일이 생기면
[analytics.google.com](https://analytics.google.com) → 관리(왼쪽 아래 톱니) →
데이터 스트림 → 웹 → **측정 ID**(`G-`로 시작).

**속성(Property)은 사이트마다 따로 만든다.** 한 속성 안에 웹 스트림을 둘 두면
두 사이트의 방문이 한 보고서에 섞이고 세션이 사이트를 넘나든 것처럼 잡힌다 —
GA가 스트림을 추가할 때 띄우는 경고가 그 얘기다. 새 사이트에는 스트림이 아니라
**속성을 새로 만들고** 그 안에 웹 스트림 하나를 둔다.

둘 다 비어 있어도 코드는 그대로 얹혀 있어도 된다 — 비면 그냥 아무것도 하지 않는다.
배포는 기본 브랜치에 올라가야 사이트에 나타난다 (「배포」 참고). 확인은 GA4
**보고서 → 실시간**, 사이트를 열고 30초 안에 숫자가 오른다.

### 켜지는 곳은 배포된 도메인뿐이다

`ga.js`의 `HOSTS`에 적은 도메인에서만 켜진다. 이유가 둘이다.

- **회귀 테스트가 흔들린다.** `npm test`는 `networkidle`을 기다리는 검사가 여럿이라,
  localhost에서 GA를 켜면 매번 바깥 스크립트를 받으러 나가느라 남의 서버 사정에 걸린다.
- **내 손장난이 통계에 섞인다.** 고치면서 백 번 여닫은 것이 방문자 숫자에 들어가면
  숫자가 거짓말을 한다.

커스텀 도메인(`dada.town`)을 붙이면 `HOSTS`에 한 줄 더한다. **거기 없는 주소에서는
`window.dadaTrack()`이 빈 함수로 서 있다** — 부르는 자리에 조건문을 두지 않기 위해서다.

### 로컬에서 확인하기

주소 끝에 **`?gadebug`**를 붙이면 실제로 보내는 대신 콘솔에 찍힌다.
어느 자리에서 무엇이 나가는지 로컬에서 그대로 볼 수 있다.

```
http://localhost:8000/?gadebug         → [ga:off] district_open {district: school, items: 4}
http://localhost:8000/game/?gadebug
```

검색은 글자마다 보내지 않는다. `아` · `아니` · `아니그`가 따로 쌓이면 아무 말도 안 남으므로,
**손이 멎고 1.2초 뒤 두 글자 이상일 때만** 한 번 보낸다.

이벤트 이름은 GA4에서 하루 안에 저절로 잡히지만, **함께 보낸 값(`district`·`item` 같은
매개변수)은 등록해야 보고서에 뜬다** — 관리 → 사용자 지정 정의 → 사용자 지정 측정기준
만들기 → 범위 `이벤트`, 매개변수 이름을 표의 이름 그대로. 등록 전 데이터는 소급되지 않으니
쓸 것부터 먼저 등록해 두는 편이 낫다. 등록 없이도 **실시간 → 이벤트 이름**에서는
바로 보인다.

### 붙는 자리는 세 곳이다

`<script src="/ga.js" defer>` 한 줄이 `index.html` · `game/index.html` ·
**`tools/build_list.py`의 템플릿**(→ `list.html`)에 들어 있다. 세 번째를 잊으면
`/list.html`만 조용해진다 — 크롤러가 실제로 읽는 페이지라 오히려 아까운 자리다.
`npm test`가 세 곳을 다 지킨다.

### 존이 아닌 주소에 걸어야 할 때 — 「호스트 이름을 직접 적는」 길

**지금은 이 길로 안 간다** (2026-08-24). `dada-town.com`이 Cloudflare 존이라
대시보드가 알아서 비콘을 넣어 주기 때문이다 — 아래 「방문 통계」를 먼저 본다.
여기 남긴 것은 **존이 아닌 주소**(`*.workers.dev`, 남의 호스팅 등)에 다시 걸
일이 생겼을 때의 길이다.

그런 주소는 Web Analytics의 사이트 목록에 안 뜬다 (거기 뜨는 건 이 계정의
존뿐이다). 그래서 이렇게 만든다.

1. Cloudflare 대시보드 → 왼쪽 **Analytics → Web analytics** → **Add a site**
2. 호스트 이름 칸에 `dada-portfolio.stupidpoohh.workers.dev`를 **직접 타이핑**한다
3. 드롭다운 아래에 뜨는 **`Click here to use "..." which does not belong to
   Cloudflare websites`**를 고른다 — 목록에서 고르는 게 아니다
4. 다음 화면(Installation)이 주는 스니펫에서 **`token` 값만** 꺼내
   `ga.js`의 `CF_TOKEN`에 넣는다. 비콘 태그 자체는 `ga.js`가 만든다

`CF_TOKEN`이 비어 있으면 비콘을 아예 부르지 않는다. GA와 같은 `HOSTS` 가드 아래에
있으므로 localhost에서는 이쪽도 조용하다.

GA와 겹쳐도 상관없지만 **숫자는 서로 다르게 나온다.** Cloudflare 쪽이 대체로 크다 —
쿠키를 심지 않아 광고 차단기에 덜 걸리기 때문이다. GA는 「무엇을 눌렀나」,
Cloudflare는 「몇 명이 왔나」로 나눠 읽는 편이 낫다.

**어느 쪽이든 숫자는 실제보다 적다.** 광고 차단기를 쓰는 방문자는 세어지지 않는다
(`ga.js`라는 파일 이름도 차단 목록에 흔히 오른다). 통계는 하한선이지 인구조사가 아니다.

## 날아다니는 쪽지

마을 위를 펄럭이며 도는 쪽지다. 누르면 **캘린더 · 플래너 · 트래커**가 한 묶음으로 열린다.
경로도 박자도 그림도 `services.json`의 `floater` 하나에서 읽는다.

### 마을 위를 도는 유일한 것이다

구름·새·자동차를 걷어낸 뒤로 **「지나가는 것」은 이것 하나뿐이라**, 움직이면 곧 눌러볼
것이라는 뜻이 된다. 그 시절 풍경들과 갈리려고 만든 신호들은 그대로 둔다 — 지금은
구별을 위해서가 아니라 그 자체로 「문」이라고 말하는 몸짓이라서다.

- **걸음이 다르다.** 한 방향으로 일정하게 흐르지 않고 길목마다 **멈춰 선다.**
  멈춤은 「기다리고 있다」로 읽힌다 — 흐르는 것과 기다리는 것은 눈에 다르다
- **파장처럼 커졌다 작아진다.** 이 뽀잉거림이 「눌러도 되는 것」이라는 신호다
  (1.8초에 ±15% — 마을의 뾰잉 2.4초와 박자를 달리해 둔다).
  **커지는 것은 안쪽 그림뿐이고 누를 자리는 고정이다** — 판정이 같이 뛰면 조준이 안 된다
- **마을 박자를 타지 않는다.** 건물 · 사람 · 까마귀는 전부 2.4초 한 박자인데 쪽지의
  펄럭임은 0.55초다. 마을의 일부가 아니라 **마을 위에 온 것**이라 굳이 맞추지 않는다
- **가장 위에 뜬다.** z 7로 마을에서 가장 위라 무엇에도 가리지 않는다
- **손을 대면 멈춘다.** 호버·포커스·팝업이 열린 동안 비행이 통째로 정지한다

### 늘 잡힌다 — 「멈췄을 때만」은 되돌렸다

한때 **멈춰 선 동안만** 잡히게 해 뒀다. 지도에서 가장 높이 뜬 것이 건물 위를 지날 때
그 건물의 클릭을 가로채는 게 싫어서였는데, 실제로 써 보니 **한 바퀴의 5분의 1만 눌리는
물건**이 됐다. 폰에서는 호버로 세울 수도 없어서 더 나빴다.
**누르려다 안 눌리는 문은 문이 아니다.** 되돌렸다.

지금은 위에 있는 것이 클릭을 받는다 — 원래 그래야 하는 일이고, 겹침은 이렇게 줄인다.

- **머무는 자리는 전부 건물이 없는 빈 땅이다** (`floater.path`의 `stop: true`).
  오래 겹쳐 서 있는 일이 없고, `npm test`가 그 좌표와 구역 상자를 계산해 지킨다
- **판정은 그림만큼만** 잡는다. 늘 잡히는 물건이라 그림보다 크게 잡으면 남의 자리까지 먹는다.
  그림이 70px 남짓이라 터치 기준(44px)은 그대로 넘는다

회귀 테스트에서는 쪽지를 **첫 길목(빈 땅)에 세워 두고** 건물을 누른다(`town()` 헬퍼).
쪽지가 마침 그 위를 지나느냐에 따라 검사가 흔들리기 때문이다 — 움직이는 배경을 묶어 두고
상호작용만 보는 것이다.

### 아직 주소가 없는 항목

묶음이 가리키는 `id`로 `items`에서 항목을 찾는다. 셋 중 하나다.

1. **`items`에 있으면** 그 항목 카드 — 목록과 `/list.html`에도 함께 실려 있는 것
2. **묶음 쪽에만 주소가 적혀 있으면** 그것으로 카드를 만든다.
   아직 **만든 시기(`date`)를 못 받아 `items`에 못 올린 것**이 여기 머문다.
   주소는 살아 있으니 눌러서 갈 수는 있지만, 목록에는 아직 안 나온다
3. **주소가 아예 없으면 「준비 중」** — 누를 수 없는 카드다.
   없는 곳으로 가는 링크를 만들지 않기 위해서다(까마귀와 같은 규칙)

`items`에 그 `id`로 항목이 생기는 순간 ①로 올라간다.

```json
"floater": {
  "w": 7,                         // 지도 폭 기준 %
  "dur": 52,                      // 한 바퀴 도는 데 걸리는 초
  "path": [
    { "at": [14, 80], "stop": true },   // stop이 붙은 길목에서만 멈추고, 멈춘 동안만 잡힌다
    { "at": [7, 52] }                   // 나머지는 지나가기만 한다 (건물 위여도 된다)
  ],
  "frames": { "down": "note-down.png", "mid": "note-mid.png", "up": "note-up.png" },
  "bundle": { "title": "매일 쓰는 것들", "items": [{ "id": "calendar", "name": "캘린더", "icon": "🗓" }] }
}
```

### 쪽지 시트 자르기

```
pip install pillow numpy
python3 tools/cut_note.py     # assets/sprites/note.png → cut/note-down · note-mid · note-up
```

`cut_crow.py`와 같은 이유로 `cut_sprites.py`를 그대로 못 쓴다 — 번갈아 보여주는
프레임은 **장끼리 눈금과 자리가 어긋나면 안 되는데**, 날개를 크게 편 장은 상자가 더 커서
각자 높이를 맞추면 쪽지가 장마다 커졌다 작아진다.

**기준점은 종이다.** 날개는 장마다 자리가 크게 바뀌지만 종이는 거의 그대로다.
종이만 골라내는 방법은 색이다 — **종이는 크림색이라 R이 B보다 확실히 높고,
날개는 흰색이라 그렇지 않다.** `R - B`로 갈린다.

시트에는 여섯 자세가 있고 마을에는 셋만 쓴다. 어느 자세를 쓸지는 `cut_note.py`의
`FRAMES`에서 고른다 — 지금은 날개가 **아래 → 옆으로 크게 → 위**로 훑는 세 장이다.
원본 시트(`assets/sprites/note.png`)는 다른 시트와 마찬가지로 `.gitignore`에 있다.

## 카페 앞 까마귀 Croww

PlayGrown의 마스코트다. 카페 건물을 누르면 팝오버가 항목을 다 보여주고,
**까마귀를 누르면 그 기록만 열린다** — 세모집 우편함과 같은 「물건마다 문이 하나씩」이다.
링크(`<a>`)라 JS가 없어도, 새 탭으로 열어도 동작한다.

문은 **셋 중 하나**로 열린다.

| `mascot`에 있는 것 | 까마귀가 되는 것 |
|---|---|
| `item` (주소가 있는 항목) | 그 문서로 가는 **링크**(`<a>`) |
| `item` 없이 `column`만 | 그 글을 제자리에서 펴는 **버튼**(`<button>`) |
| 둘 다 없음 | **풍경** — `<span>`에 `pointer-events: none`, 스크린리더에서도 감춤 |

**지금은 가운데다.** 전시 세션을 다시 짓는 중이라(PLAN §5) 열 문서가 없고,
그 대신 **읽던 칼럼을 펴 둔다.** 눌렀는데 아무 일도 없는 것보다, 지금 손에 있는 것을
내어놓고 나머지는 준비 중이라고 말하는 편이 정직하다 — 그래도 **없는 곳을 가리키는
링크는 여전히 만들지 않는다.** 새 페이지가 올라가면 `item`을 채우면 그만이고,
그러면 링크가 다시 이기므로 칼럼은 저절로 물러난다.

칼럼 패널은 **칼럼이 먼저, 「준비 중」이 맨 아래**다. 순서가 곧 말이다 —
열자마자 준비 중부터 보이면 눌러 봤자 헛일이었다는 뜻이 되는데, 여기에는 읽을 것이
실제로 있다. 자리는 노래(확성기)와 같이 `liveBox`로 까마귀를 따라간다.

자리와 크기는 `services.json`의 `districts[].mascot`에서 읽는다.

```json
"mascot": {
  "name": "까마귀 Croww",
  "at": [65.2, 74.4],          // 발밑 좌표 (지도 % — "나" 캐릭터·사람들과 같은 규칙)
  "w": 6.6,                    // 지도 폭 기준 %. 캔버스에 날개 자리가 있어 그림은 이보다 작다
  "frames": {                  // 이름이 곧 역할이다. 순서가 아니라 이름으로 찾는다
    "rest": "crow-side.png",
    "flap": "crow-fly.png",
    "tilt": "crow-look.png"
  },
  "item": "playgrown"          // 누르면 이 항목의 문서로 간다 (/case/playgrown.html)
}
```

**`column`은 걷었다** (2026-08-21). 문서가 없는 동안 까마귀가 대신 펴 보이던 글
상자였는데, 그 글은 이제 케이스 스터디 첫 절에 있다 — **같은 것을 두 군데서 읽게
두지 않는다.** `app.js`에는 아직 읽는 코드가 남아 있으니 되살릴 일이 생기면
`mascot.column`을 도로 채우면 된다.

**세 가지가 중요하다.**

- **움직이는 것은 안쪽 그림(`.crow-figure`)뿐이고 링크 상자는 가만히 있는다.**
  "나" 캐릭터와 같은 이유다 — 누를 자리가 흔들리면 조준이 안 된다. 폰에서 20px 남짓이라
  판정 영역을 `::after`로 56px까지 넓혀 깐다
- **걸음이 달라야 같은 요소로 안 읽힌다.** 마을과 같은 2.4초 한 박자를 타되,
  건물은 두 번 숨쉬고 우편함은 한 번 크게 뛰고 **까마귀는 한 번 퍼덕이고 한 번 갸웃한다.**
  `crow-idle`·`crow-frame`은 `IDLE_ANIMS`에 들어 있어 마을 박자에 함께 맞춰진다 —
  빼먹으면 그 자리만 딴 박자로 논다
- **퍼덕임과 갸웃은 그림 세 장을 번갈아 만든다.** 이 마을에는 프레임 애니메이션이 없고
  transform만 쓰는데, 날개가 실제로 올라가려면 그림이 여러 장이어야 했다.
  세 장을 겹쳐 두고 `steps(1)`로 갈아 끼우므로 사이가 섞이지 않는다.
  기울임(`rotate`)은 거들기만 한다 — `crow-look`이 이미 고개를 들고 있어서,
  여기서 많이 돌리면 갸웃이 아니라 넘어지는 것처럼 보인다

### 까마귀 시트 자르기

`cut_sprites.py`를 그대로 못 쓴다. 그 스크립트는 스프라이트마다 자기 bounding box에
맞춰 따로 축소하는데, **까마귀는 번갈아 보여주는 프레임이라 장끼리 눈금과 자리가
어긋나면 안 된다.** 날개를 편 장은 상자가 더 크므로 각자 높이를 맞추면 몸통 크기가
장마다 달라지고, 갈아 끼울 때 새가 커졌다 작아진다.

```
pip install pillow numpy
python3 tools/cut_crow.py      # assets/sprites/crow.png → cut/crow-side · crow-fly · crow-look
```

**기준점은 눈이다.** 처음엔 부리 끝에 맞췄는데 장마다 부리가 몸에서 나온 정도가 달라
갈아 끼울 때 몸이 옆으로 미끄러졌다. 눈은 어느 장에서나 같은 것이라, 눈을 포개면
머리가 제자리에 있고 나머지(날개 · 꼬리 · 자세)만 바뀐다. 온몸에서 유일하게 밝은
크림색이라 색으로 바로 찾는다.

시트에는 여섯 자세가 있고 마을에는 셋만 쓴다 (`cut/`은 「지금 쓰는 것」만 두는 자리다).
앞모습·뒷모습을 쓸 일이 생기면 `cut_crow.py`의 `FRAMES`에 이름을 더한다.
원본 시트(`assets/sprites/crow.png`)는 다른 시트와 마찬가지로 `.gitignore`에 있다.

## 첫 방문 안내 · 투어가이드 (`onboarding.js`)

처음 온 사람에게 **다원이 마을 밖에서 걸어 들어와** 인사하고, 앞으로 어떻게 볼지를
고르게 한다. 고른 뒤는 둘 중 하나다 — 그냥 마을(=원래 사이트)이거나, 같은 지도 위에서
세 곳만 짚어 주는 투어다. **어느 쪽도 다른 페이지로 보내지 않는다.**

```
바깥 → 걸어 들어옴 → 대사 셋 → 갈림길 ┬ 탐험하기      → 원래 마을
                                     └ 투어가이드    → 1/3 → 2/3 → 3/3 → 원래 마을
```

대사 단추는 **첫 두 줄만 「다음」 + 「안내 건너뛰기」이고, 마지막 줄은 「반가워!」
하나뿐이다.** 세 줄을 다 읽은 사람에게 「건너뛸래요?」는 이미 늦은 말이라(건너뛸 것이
안 남았다) 그 자리에서 뺐다. 남는 단추는 인사를 받는 말 하나여야 한다.

### 왜 파일이 따로인가

`app.js`는 마을을 그리는 곳이고, 이것은 마을 위에 **잠깐** 얹히는 겹이다. 섞어 두면
나중에 안내를 걷어낼 때 마을까지 들춰야 한다. 그래서 안내가 마을에 하는 일은
**이미 있는 문을 대신 눌러 주는 것**(`door.click()`)뿐이다 — 항목을 어떻게 여는지
(책이냐 · 외부 링크냐 · 구역 패널이냐)를 `onboarding.js`는 **하나도 모른다.**
그 덕에 새 항목이 늘거나 여는 방식이 바뀌어도 여기는 고칠 게 없다.

`app.js`와 닿는 자리는 딱 하나다 — `init()` 끝의 두 줄.

```js
window.dadaTown = { data };
document.dispatchEvent(new CustomEvent('dada:ready', { detail: { data } }));
```

`window.dadaTown`에도 남기는 이유: 이벤트는 한 번 지나가면 끝이라, 그때 아직 안 붙어
있던 쪽은 영영 못 받는다. `onboarding.js`가 통째로 없어도 이 두 줄은 그냥 아무도
안 듣는 말이 된다.

### 걸어 들어오는 것이 핵심이다

`fade-in`으로 바꾸지 않는다. 이 안내가 하려는 말이 **「만든 사람이 직접 마중 나왔다」**
라서, 프레임을 넘어오는 그 순간이 문장 노릇을 한다.

그래서 안내 겹(`.onb`)은 `position: fixed`다. `.map` 안에 두면 `overflow: hidden`에
잘려 **밖에서 들어오는 것 자체가 안 보이고**, `.map-holder`에 두어도 지도 왼쪽 여백
까지밖에 못 나간다(넓은 화면에서 그건 200px도 안 된다). 자리는 JS가 지도에서 재서
넣고, 굴리거나 창이 바뀌면 다시 잰다.

걷기 스프라이트는 **없다** — `me.png`는 한 장뿐이다. 그래서 걸음은 반동으로만 만든다.
껍질이 셋인 것은 **한 요소에 애니메이션 둘을 걸 수 없어서**다(나중 것이 앞 것을 지운다).
확성기가 호버 확대를 `.horn-zoom`에 따로 거는 것과 같은 수다.

| 껍질 | 하는 일 |
|---|---|
| `.onb-char` | 가로 이동 (`transition: left`) — 걸어 들어오고 나간다 |
| `.onb-step` | 걸음(0.34초) · 착지 · **숨쉬기(2.4초)** — 갈아드는 상태 하나 |
| `.onb-beat` | 말이 바뀔 때 **한 번 끄덕임** — 숨쉬기를 안 끊고 겹쳐 돈다 |

**걷는 시간도 걸음 박자도 「거리에서」 나온다.** 둘 다 고정이었던 적이 있다
(1.5초 · 0.34초). 그런데 다원이 가는 거리는 화면마다 다르다 — 폰에서는 200px 남짓인데
1440px 데스크톱에서는 600px이 넘는다. 같은 시간에 세 배를 가니 **한 걸음에 몸폭의 두
배씩** 나아갔고, 그게 「슝 날아가면서 통통거린다」로 보였다(2026-08-25).

    시간 = 거리 / SPEED(210px/s)             어느 화면에서나 비슷한 속도로 걷는다
    박자 = 한 주기에 몸폭의 STRIDE(0.62)배   빨리 갈수록 발을 빨리 놓는다

**그런데 그것만으로는 모자랐다.** 보폭 비율은 맞았는데 데스크톱이 「두두두두 둔탁」
했다 — 초당 **9.3번**씩 들썩였다(폰은 5.9번). 걷는 게 아니라 떠는 것으로 보인다.

원인은 **다원이 건너야 할 거리에 비해 너무 작았다**는 것이다. 96px짜리가 609px를
건너면 제 몸길이의 6.3배다. 보폭을 몸에 맞춰 두면 그만큼 발을 자주 놓아야 한다.
폰은 2.75배뿐이라 처음부터 멀쩡했다. 그래서 **넓은 화면에서 다원을 키웠다**
(지도 폭의 0.135 → **0.24**). 크기가 예쁘고 말고의 문제가 아니라 **걸음이 그것으로
정해진다.**

| | 몸폭 | 거리 | 시간 | 걸음 | 초당 | 한 주기 ÷ 몸폭 |
|---|---|---|---|---|---|---|
| PC 1440 | 169px | 682px | 2.2초 | 0.338초 | **5.9번** | 0.62배 |
| PC 1280 | 169px | 602px | 2.2초 | 0.340초 | **5.9번** | 0.55배 |
| 폰 390 | 72px | 198px | 1.5초 | 0.338초 | **5.9번** | 0.62배 |

**한 걸음의 모양도 고쳤다.** 위아래를 `ease-in-out` 하나로 오가면 사인파라 몸이
둥둥 뜬 채 흔들리는 것으로 보인다. 걸음은 그런 게 아니다 — 톡 차고 오르고(빠르게),
떨어지고(점점 빨라지고), 딛는 순간 눌리고, 아주 잠깐 머문다. 그 네 마디를 키프레임
마다 다른 easing으로 만든다(그래서 `animation`의 timing-function이 `linear`다 —
키프레임에 적은 것이 먹히도록).

**폰 값(1.5초 · 0.34초)이 기준이다** — 다원님이 「모바일 모션이 훨씬 좋다」고 한 그
값이라, 식에 폰을 넣으면 그 둘이 그대로 나오도록 SPEED·STRIDE를 골랐다.
검사는 **초가 아니라 이 비율**을 못 박는다. 화면 크기가 바뀌어도, 나중에 상수를
손봐도, 비율만 지켜지면 걷는 것으로 보인다.

**도착했다고 목석이 되지 않는다.** 한때 착지(`onb-land`, `both`)가 마지막 프레임을
붙들고 끝이라, 말풍선이 세 번 넘어가는 동안 내내 얼어 있었다. 착지가 끝나는 자리에서
숨쉬기로 갈아탄다.

숨쉬기 박자는 **마을과 같은 2.4초**다 — 건물도 사람들도 지도 위의 "나"도 그 박자다.
**다만 폭은 훨씬 작다.** 지도 위의 "나"는 20px 남짓이라 18%씩 뛰어야 겨우 보이지만,
여기 다원은 그 여섯 배(130px 안팎)라 같은 폭으로 뛰면 화면이 출렁인다. 실측으로
숨쉬기는 9px, 끄덕임은 21px 폭이다 — 박자만 같이 가고 진폭은 줄인다.

### 움직임을 줄여 달라고 한 사람 — 여기를 두 번 잘못 만들었다

**① 처음에는 전부 껐다**(0.01초 순간이동). 다원이 뿅 나타나고 말풍선도 뿅 떠서
안내가 통째로 사라진 것처럼 보였다. **② 다음에는 가로 이동만 살렸다**(0.52초).
그런데 뒤뚱거림이 없으니 걷는 게 아니라 **미끄러지는 것**이 됐다 — 다원님이
「계속 슝 나와」라고 했다(2026-08-25).

기준을 잘못 잡아서 그랬다. 여기서 줄일 것은 **화면을 가로지르는 거리**지 제자리에서
몸이 들썩이는 폭이 아니다. 그리고 **이 사이트의 바탕**을 봐야 한다 — `styles.css`는
줄이기 사용자에게도 건물을 숨쉬게 하고, 까마귀를 퍼덕이게 하고, 쪽지를 지도 위로
계속 날린다(`prefers-reduced-motion`을 보는 곳은 책 팝업 하나뿐이다).
**안내만 혼자 얼어 있으면 그게 도리어 어긋난 것이다.**

| | 평상시 | 줄이기 |
|---|---|---|
| 가로 이동 | 1.5초 | **0.9초** |
| 걸음 (뒤뚱뒤뚱) | 8% · 0.34초 | **4% · 0.44초** (`onb-step-soft`) |
| 착지 · 숨쉬기 · 끄덕임 | 있음 | **그대로** — 지도 위 "나"가 이미 더 크게 숨쉰다 |
| 말풍선·투어 카드 뜰 때 | translate + scale | **페이드**만 (WCAG가 권하는 갈음) |
| 투어 테두리 숨쉬기 | 있음 | **끔** — 되풀이되며 시선 끄는 것이 하는 일이 강조뿐이라 |

**여기가 드문 예외가 아니라는 것도 알아둘 값이 있다.** iOS는 이 값을 「동작 줄이기」
뿐 아니라 **저전력 모드에서도** 켠다. 윈도우는 「설정 → 접근성 → 시각 효과 →
애니메이션 효과」, 맥은 「손쉬운 사용 → 디스플레이 → 동작 줄이기」다. 배터리가
닳거나 성능 설정을 만진 사람은 누구나 이 길로 들어온다.

**「슝」인지 「뒤뚱뒤뚱」인지 헷갈리면** 콘솔에서
`matchMedia('(prefers-reduced-motion: reduce)').matches`를 보면 된다.

### 「탐험하기」를 고르면 다원은 제자리로 걸어 돌아간다

마중 나온 이야기를 마중 나온 자리에서 끝내면 「사라졌다」로 읽힌다. 그래서 지도 위
"나"(`services.json`의 `character`)가 원래 서 있던 그 자리로 **뒤뚱뒤뚱 걸어가서
거기서 겹쳐 바뀐다.** 그래야 지도 위의 그 캐릭터가 왜 거기 서 있는지도 말이 된다.

- **목적지는 좌표로 적지 않는다.** `.me-spot`을 실제로 재서 쓴다 — 안내 중에는
  `visibility: hidden`이지만 자리는 그대로 차지하고 있어 잴 수 있다. 좌표를 베껴
  두면 `character`를 옮겼을 때 여기만 옛 자리에 남는다.
- **버튼을 재지 안쪽 그림을 재지 않는다.** 흔들리는 것은 `.me-figure`고 버튼은
  가만히 있다(styles.css). 안쪽을 재면 착지점이 숨쉬기 박자만큼 흔들린다.
- 가로로 가면서 **작아지고 위로 조금 오른다** — 멀어지는 것처럼 보이려면 그래야 하고,
  도착했을 때 크기가 지도 위 "나"와 같아야 겹쳐 바뀌는 것이 티가 안 난다.
  (1440px에서 실측: 중심 473 → 745, 폭 96 → 38, 밑변 671 → 625)
- 도착하면 **지도 위 "나"를 먼저 켜고** 안내 쪽을 흐린다. 순서가 반대면 한 프레임
  동안 아무도 없는 자리가 생겨 깜빡인 것처럼 보인다.

**「탐험하기」에만 붙인다.** 투어는 지도가 곧바로 필요하고, 「건너뛰기」는 「그만 보고
싶다」는 뜻이라 둘 다 1.2초를 더 붙들면 안 된다 — 그쪽은 짧은 페이드로 끝낸다.

#### 돌아설 때 — 앞모습과 뒷모습

다원은 **돌아서서** 걸어간다. 앞모습(`me.png`)과 뒷모습(`me-back.png`)을 겹쳐 두고
0.16초 크로스페이드로 갈고, 도착해서 지도 위 "나"(앞모습)로 다시 겹쳐 바뀐다.

두 장은 **같은 캔버스(423×558)·같은 밑변**이어야 한다. 아니면 돌아설 때 키가 튀거나
발이 어긋난다. `tools/cut_me_back.py`가 그렇게 맞춰 떠낸다 — 알파 상자로 바짝 자르고,
높이를 앞모습에 맞추고(가로세로 비가 앞 0.758 · 뒤 0.738로 거의 같아 억지로 늘일 일이
없다), 앞모습과 같은 캔버스에 가로 가운데·아래 맞춤으로 얹는다. 캔버스 크기를 박아
두지 않고 **앞모습에서 읽어 오므로**, 앞모습을 다시 뜬 뒤에는 이것도 다시 돌린다:
`python3 tools/cut_me.py && python3 tools/cut_me_back.py`. 맞았는지는 두 장을 반씩
겹쳐 보면 안다 — 머리·옷깃·치맛단·발이 같은 줄에 오면 된다.

포개는 것은 `.onb-beat`가 맡는다(`position: relative` + `.onb-back`이
`absolute; inset: 0`). 그래서 걸음의 들썩임도 두 장이 같이 탄다.

`onboarding.js` 맨 위 `BACK`을 비우면 앞모습 그대로 물러난다 — 그림이 없다고 연출이
멈추지는 않게. **없는 파일 이름을 적어 두면 안 된다**: 404가 콘솔에 오류로 남고
`npm test`의 「JS 오류」 절이 그것을 잡는다.

**원본은 루트에 있다.** 다원님이 GitHub 웹으로 올리는 자리가 거기라서다.
`town-background.png`와 같은 규칙으로 지우지 않고 `.assetsignore`로 배포에서만 뺀다 —
안 그러면 `/me-back.png`로 452KB가 그대로 배포된다. 적을 때 **슬래시를 반드시**
붙인다(`/me-back.png`): 안 붙이면 gitignore 규칙상 어느 깊이에서나 걸려서
정작 사이트가 쓰는 `assets/sprites/cut/me-back.png`까지 같이 빠진다. 여기서 실제로
한 번 밟았다.

### 케이스 스터디를 보고 돌아오면 투어가 이어진다

투어의 셋 중 PlayGrown만 **같은 탭**으로 간다. 거기서 다 보든, 뒤로가기를 하든,
「돌아가기」를 누르든 전부 `/`로 오는데 — 그때 투어가 없고 다원이 처음부터 다시
인사했다(2026-08-25). 방금 인사를 듣고 투어를 고른 사람에게 다시 인사하면 안내가
아니라 **벽**이 된다.

떠나기 직전에 몇 번째였는지를 `sessionStorage['dada.tourAt']`에 적고, 돌아오면
**인사를 건너뛰고 그 자리에서 잇는다.** `localStorage`가 아니라 `sessionStorage`인
것은 탭을 닫으면 사라져야 해서다 — 다음에 새로 온 사람에게 남의 투어 자리가
이어지면 안 된다. 꺼낼 때 지우고(한 번만 잇는다), 투어를 접을 때도 지운다.

**케이스 스터디에서 마을로 나오는 문이 셋이다.** 왼쪽 위 「← 마을 지도로 돌아가기」
(`.doc-back`의 `<a href="/">`), 양 끝에서 한 번 더 미는 화살표(`location.href='/'`),
브라우저 뒤로가기. **셋 다 같아야 한다** — 하나만 이어진다는 말을 들어서(2026-08-25)
검사가 셋을 다 지나간다. 뒤로가기는 페이지가 통째로 되살아날 수 있어서(bfcache)
스크립트가 다시 안 돈다 — `pageshow`로 그 길도 받는다.

**자리는 읽을 때가 아니라 정말 이어 붙인 뒤에 지운다.** 한때 읽으면서 지웠는데,
읽고 나서 「그런데 문이 하나도 안 그려져 있네」로 되돌아가는 길이 있어서 그때 자리가
조용히 날아갔다 — 돌아왔는데 투어가 없고 인사가 다시 나오는 꼴이다.

그래서 `build(greet)`가 둘로 갈린다 — 이어 붙일 때는 덮개도 다원도 만들지 않는다.
`app.js`의 `open()`이 돌려주는 `leaves`가 「정말 떠나느냐」를 말해 준다. `stays`와
같은 말이 아니다: 책은 남지도(지도를 통째로 덮는다) 떠나지도 않는다.

### 마을 나가는 길의 표지판 — 배웅

다리 왼쪽, 마을 밖으로 난 길목에 표지판(`services.json`의 `sign`)이 선다. 누르면
**다원이 지도 위 제자리에서 총총 뛰어나와** 배웅한다 — 들어올 때의 반대다. 그때는
화면 밖에서 걸어 들어왔고, 여기서는 마을 안에서 앞으로 나오므로 앞모습으로 온다.

    와줘서 고마워요.                         [다음]
    혹시 저에게 남기고 싶은 말이 있나요?
        [ 인사 남기기 👋 ]      숫자 하나
        [ 짧은 메시지 남기기 ]   글
        [ 연락하기 ]            메일
          그냥 둘러볼게요        아무것도 안 남기고 닫는다

**셋이 하는 일이 다 다르다.** 남길 말의 무게가 저마다 달라서 문도 셋이다.
넷째 줄은 문이 아니라 **나갈 길**이다 — 고르는 차례에는 아무 데나 눌러도 안
넘어가게 해 두었으므로(덮개의 `quiet`), 이것이 없으면 셋 다 마음에 안 드는
사람은 갇힌다. 키보드가 없는 폰에는 Esc도 없다.

- **표지판을 가리지 않는다.** 다원은 지도 폭의 4분의 1이라 인사할 때 자리(15%)에
  그대로 서면 표지판(6%)을 통째로 덮는다 — 눌러서 부른 것이 가려지면 무엇에 대한
  대답인지 알 수 없다. 배웅 때는 오른쪽(32%)에 비켜 선다.
- **손잡이(`window.dadaBye`)는 모듈이 뜨는 순간 내건다.** `boot()` 안에서 내걸면
  늦다 — 지도가 표지판을 그릴 때 그 이름이 없으면 「누를 수 없는 풍경」으로 세운다.
- **「짧은 메시지」는 창을 먼저 연다.** 다원이 걸어 돌아가는 1.2초를 기다렸다 열면
  누른 사람은 그동안 아무 일도 안 일어난 줄 안다. 창은 새로 만들지 않고 푸터 👋가
  여는 그 창을 그대로 쓴다(`window.dadaTown.say`).

#### 덮개는 한 곳에서만 만든다 (`makeScrim`)

한때 `greeter()`와 `bye()`가 저마다 덮개를 만들었다. 표지판을 누르면 `bye()`가
하나 만들고 이어서 `greeter()`가 **또 하나** 만들면서 앞의 것이 변수에서 떨어져
나갔고, 끝날 때 뒤엣것만 치워졌다. 남은 덮개는 화면 전체를 덮는 투명한 판이라
**배웅이 끝난 뒤로 마을이 통째로 안 눌렸다** — 아무것도 안 보이는데 아무것도
안 되는, 제일 알아채기 어려운 종류의 고장이다.

지금은 `makeScrim()` 하나가 만들고(이미 있으면 그것을 쓴다), 어느 차례인지는
그 안의 한 핸들러가 `phase`로 가른다. 끝낼 때는 변수가 가리키는 것만이 아니라
**화면에 있는 `.onb-scrim`을 다 걷는다** — 덮개는 안 보이는 것이라 남아도 눈에
안 띄므로, 세지 않고 쓸어 담는 편이 맞다. 검사가 「덮개는 하나만 선다」,
「끝나면 하나도 안 남는다」, 「목록이 도로 열린다」로 셋 다 지킨다.

#### 손 인사는 글이 아니라 숫자다

남길 말이 없는 사람도 「다녀갔다」는 말은 하고 싶을 수 있고, 그 말에 폼을 세우면
아무도 안 한다. 그래서 화상회의의 리액션처럼 **손 하나가 눌린 자리에서 떠올랐다
사라지고**, 서버에는 한 번 셌다고만 알린다(`POST /api/wave`).

날짜별로 센다(`v:2026-08-25`). 통짜 하나로 안 세는 이유는 **KV에 「1 늘리기」가
없어서**다 — 읽고 더해서 쓰는 수밖에 없는데, 통짜 하나면 같은 순간에 둘이 누를
때마다 하나가 덮여 사라진다. 날짜로 갈라 두면 부딪힐 일이 훨씬 적고 언제 사람이
왔는지도 같이 남는다. 관리자 화면(`GET /api/word?key=…`)이 글과 함께 `hello`(총)와
`days`(날짜별)를 준다.

**떠오르는 것은 눌린 그 자리에서 시작한다.** 화면 한가운데에서 뜨면 내가 누른 것과
이어지지 않아 「무슨 일이 일어났지」가 된다. 서버가 못 받아도 손은 이미 떠올랐다 —
인사는 우리끼리 한 일이라 거기서 실패했다고 사람에게 사과할 일은 아니다.

### 건너뛰어도 걸어서 돌아간다

한때 「건너뛰기」만 짧은 페이드로 끝냈다. 그러면 안내를 건너뛴 사람만 다원이 뿅
사라지는 것을 본다 — **건너뛰는 것은 인사를 그만 듣겠다는 뜻이지 인사한 사람이
없던 일이 되라는 뜻이 아니다.** 지금은 투어만 빼고 전부 제자리로 걸어 돌아간다
(투어는 지도가 곧바로 필요해서 그때만 짧게 끝낸다).

### 안내 중에는 마을이 잠깐 조용하다

- 지도 위 "나"를 숨긴다(`body.dada-onboarding .me-spot`). 다원이 앞으로 나와 인사하는
  동안 마을 안에도 같은 사람이 서 있으면 둘이 된다.
- 지도 아래 안내 문구도 숨긴다 — 무엇을 눌러야 하는지는 지금 말풍선이 말하고 있다.
  `.hint.gone`과 같은 `visibility`라 자리는 남아 아래가 들썩이지 않는다.

### 투어 — 그늘은 넉 장이다

**구멍 뚫린 덮개 한 장이 아니다.** `clip-path`로 구멍을 내면 한 장으로 되지만,
그 구멍이 **손가락까지 통과시키느냐**는 브라우저마다 다르다. 위·아래·왼·오른 넉 장으로
둘러싸면 가운데는 **애초에 덮인 적이 없어서** 추천 대상은 언제나 그냥 눌린다.
나머지는 이 넉 장이 받아내 막는다.

넉 장을 `.map` **안**에 넣는 것도 이유가 있다 — 거기 `overflow: hidden`이 있어 그늘이
지도 밖으로 새지 않는다. **화면 전체가 어두워지는 게 아니라 지도만** 어두워진다.
따로 다크 테마를 만들지 않는다. 투어는 마을의 다른 테마가 아니라 **한 상태**다.

구멍은 판정 영역(버튼 전체)이 아니라 **눈에 보이는 그림**(`.pop` · `.crow-figure` …)에
맞춘다. 회사 구역 상자는 지도의 18×34%나 돼서, 그대로 뚫으면 무엇을 가리키는지
알 수가 없다.

### 「열어보기」는 문이 아니라 그 항목을 연다

예전에는 지도 위 문을 대신 눌렀는데(`door.click()`), **회사 건물은 구역 패널을 여는
문**이라 「사업팀 운영보드」를 누른 사람에게 회사 목록이 떴다(2026-08-25). 투어가
가리키는 것은 구역이 아니라 항목이므로 항목을 여는 문으로 간다 —
app.js가 `window.dadaTown.open(id, from)`으로 내준다.

그 함수는 **목록·구역 패널이 쓰는 그 카드를 실제로 만들어 누른다.** 여는 규칙
(새 탭이냐 · 책이냐 · 노래냐 · 그냥 이동이냐)이 `card()` 한 군데에만 있어야 나중에
갈릴 때 같이 갈린다. 화면 밖에 잠깐 붙였다 떼는 이유는 **떼어 둔 `<a>`는 `click()`해도
브라우저가 따라가지 않아서**다.

**그리고 투어를 끝내지 않는다.** 셋 중 둘(사업팀 운영보드 · 아니그래서)은 바깥 앱이라
새 탭으로 열린다 — 보고 돌아오면 투어가 그 자리에 있어야 한다. 예전에는 열자마자
끝나서 돌아왔을 때 아무것도 없었다. 끝내는 것은 **이 페이지를 떠날 때**뿐이고
(PlayGrown은 같은 탭에서 케이스 스터디로 간다), 그건 투어가 살아 있을 자리가 없어서다.
`open()`이 돌려주는 `stays`가 그 판단이다.

밝혀 둔 것을 손으로 직접 누르면 그때는 **그늘을 먼저 걷고** 마을이 원래 하던 일을
한다(`#map`의 캡처 단계에서 먼저 걷는다). 순서가 뒤집히면 구역 패널이 그늘 밑에서
열려 아무것도 안 보인다.

### 투어를 바꾸려면

`onboarding.js` 맨 위 세 줄이 전부다.

```js
const TOUR = [
  { item: 'sindorang-demo' },
  { item: 'playgrown', door: '.crow-spot' },
  { item: 'anih' },
];
```

이름·설명·주소는 여기 적지 않는다 — id로 `services.json`에서 찾아 쓴다. 한 군데에만
적혀 있어야 어긋나지 않는다. `door`를 안 적으면 그 항목이 사는 구역의 건물이 문이다.
카페에는 항목이 둘인데 PlayGrown은 까마귀가 따로 물고 있어서 그것만 적어 준다 —
안 그러면 2번과 3번이 같은 건물을 두 번 밝힌다.

### 언제 뜨는가 — **올 때마다** (2026-08-25 바뀜)

| 상황 | 뜨나 |
|---|---|
| 그냥 들어옴 · 새로고침 · 뒤로가기로 돌아옴 | **뜬다** |
| `?intro` | 뜬다 — **「다시 안내받기」 단추가 붙을 자리다** |
| `localStorage['dada.introOff'] = '1'` | 안 뜬다 (끄는 문. 아직 켜는 UI는 없다) |
| `#art` 처럼 해시로 곧장 온 사람 | 안 뜬다 (볼 것을 정하고 온 사람 앞을 막지 않는다) |
| `?tune` (좌표 재는 중) | 안 뜬다 |

처음에는 첫 방문에만 띄우고 `localStorage`에 다녀갔다고 적었는데, **다원님이
뒤집었다** — 새로고침하면 다시 나와야 한다. 그래서 지금은 **아무것도 적지 않는다.**
대신 끄는 칸(`dada.introOff`)만 남겨 뒀고, 지금 그것을 쓰는 것은 회귀 테스트뿐이다
(검사 페이지 서른몇 개가 매번 안내 덮개를 누르지 않도록).

**칸 이름을 바꾼 이유**가 있다. 먼저 올라간 판을 본 브라우저에는 예전 칸
(`dada.onboarded`)이 `'1'`로 남아 있다. 그 칸을 그대로 끄는 스위치로 재활용했다면
**그 사람들에게는 영영 안 떴을 것이다** — 다원님 폰이 그중 하나다. 뜻이 달라지면
칸도 새로 판다.

되돌리려면 `wanted()`가 `true`를 돌려줄 때 `dada.introOff`를 적게 하면 된다.
**대신 재방문자마다 같은 인사를 다시 본다는 것은 값이다** — 케이스 스터디를 열고
뒤로 돌아와도 처음부터 다시 인사한다.

### 검사할 때 주의

안내는 **올 때마다** 화면 전체에 덮개를 깐다. 그대로 두면 **마을을 누르는 검사 서른몇
개가 전부 그 덮개를 누르게 되고**, 화면에는 아무 일도 안 일어나 「지도가 죽었다」로만
보인다. 그래서 `tests/smoke.mjs`의 `watch()`가 모든 검사 페이지에 `dada.introOff`를
미리 심는다. 안내 자체는 `first()`로 끄지 않은 페이지를 따로 열어 본다.

출발점(화면 밖이었나)은 **나중에 물어서는 못 잰다** — 걸어 들어오는 데 1.5초인데
`waitForSelector`가 돌아오는 데만 그 절반이 간다. 붙는 순간을 `MutationObserver`로
잡아 둔다(관찰자 콜백은 그 일감이 끝난 뒤·다음 프레임 전에 돌아서, 출발값이 그대로
남아 있다).

### 이 페이지에서 깨기 쉬운 것

  아래로 이어진 **그냥 굴리는 문서**로 남는다. 넘기는 쪽을 골랐어도 못 넘기는 상황에서
  통째로 안 읽히는 일은 없어야 한다 — 이 되돌림을 깨지 않는다. 회귀 테스트가 지킨다
- **굴릴 수 있는 곳은 하나뿐이어야 한다.** 문서는 `100dvh`로 못 박고, 굴리는 것은
  화면 안에서만. 넘치는 화면은 `align-content: safe center` — 그냥 `center`로 두면
  화면보다 긴 절의 표제가 굴려도 안 닿는 데로 밀려난다
- **표지가 말하는 것을 지운 적이 있다.** 사실 표를 정리하다 「파일럿 1회」가 같이
  지워져서, 읽는 사람이 여덟째 화면까지 계속 운영한 가게인 줄 알고 읽었다.
  표지의 **파일럿 · 날짜 · 맡은 일**과 파일럿 절의 **접은 이유**는 회귀 테스트로
  못 박아 뒀다 (`node tests/smoke.mjs 표지가`)
- **CSS는 `assets/case/playgrown.css`로 나눈다.** 형식이 여럿이라 규칙이 꽤 느는데,
  마을 한 채를 위한 규칙을 `styles.css`에 섞으면 이후 마을을 손볼 때마다 같이 읽어야 한다
- **손으로 쓰는 페이지다.** `list.html`처럼 생성되지 않으므로 `build_list.py`를 돌려도
  덮이지 않는다. 다만 `services.json`에 항목으로 올렸으므로 목록 · `/list.html` ·
  `sitemap.xml`에는 자동으로 따라 들어간다
- **칸 사이 선은 `gap`이 아니라 겹치는 `outline`으로 긋는다.** `gap: 1px` + 부모 배경색으로
  격자를 그리면 항목 수가 열 수의 배수가 아닐 때 **빈 자리에 선 색이 그대로 드러나
  회색 띠가 생긴다.** 타일이 13개였을 때 실제로 그랬다

## 제작자에게 한마디 (`/api/word`)

푸터의 👋에서 방문자가 한마디 남기고 갈 수 있다. **이 마을에서 서버가 하는 일은 이것
하나뿐이다** — 나머지 주소는 예전 그대로 정적 에셋으로 나간다 (Workers 정적 에셋은
파일이 있는 주소를 Worker에 물어보지 않는다. 없는 주소인 `/api/word`만 `worker.js`로 온다).

### 켜져 있다

`wrangler.jsonc`의 `kv_namespaces`에 `WORDS` 네임스페이스가 붙어 있다.
이 저장소는 **기본 브랜치에 올라가면 Cloudflare가 알아서 다시 배포하므로**
(`git remote show origin`의 `HEAD branch`) 배포 명령은 따로 없다.

네임스페이스 **id는 비밀이 아니다** — 계정에 로그인하지 않으면 아무것도 못 하는
이름표라 Cloudflare 문서도 설정 파일에 그대로 적는다. 진짜 비밀인 `ADMIN_KEY`는
시크릿으로 따로 넣으므로 이 파일에 남지 않는다.

새로 만들거나 옮길 일이 생기면:

1. Cloudflare 대시보드 → Storage & Databases → KV → Create namespace → 이름 `WORDS`
   (터미널이면 `npx wrangler kv namespace create WORDS`)
2. 나온 id를 `wrangler.jsonc`의 `kv_namespaces`에 넣는다
3. 기본 브랜치에 올리면 끝

**빈 `id`를 남겨 두면 배포가 통째로 막힌다.** 떼어낼 일이 생기면 블록을 통째로
주석 안으로 되돌린다 — 그때는 서버가 503과 함께 「아직 받을 준비가 안 됐다」고
말하고, 마을의 나머지는 그대로 돈다.

### 읽기

**대시보드에서 그냥 볼 수 있다** — Storage & Databases → KV → `WORDS` → 항목 보기.
여기까지는 열쇠가 필요 없다.

주소로 받고 싶으면 시크릿을 하나 넣는다 (선택).

```
대시보드: Workers → dada-portfolio → Settings → Variables and Secrets
          → Secret 추가, 이름 ADMIN_KEY
터미널  : npx wrangler secret put ADMIN_KEY
```

그러면 `/api/word?key=<ADMIN_KEY>`로 최근 200개가 JSON으로 나온다.
시크릿은 `wrangler.jsonc`에 적히지 않으므로 **다시 배포해도 지워지지 않는다.**
터미널에서는 열쇠 없이도 볼 수 있다 — `npx wrangler kv key list --binding WORDS --remote`.

키를 `w:<시각역순>`으로 만들어 **목록이 최신순으로 저절로 정렬된다** — KV의 `list`는
키 사전순이라, 시각을 그대로 넣으면 오래된 것부터 나와 매번 뒤집어야 한다.

`ADMIN_KEY`를 안 넣었으면 **주소로 읽는 길은 아예 막힌다.** 설정 안 된 자물쇠는
열린 자물쇠다.

### 정해 둔 것

- **적는 칸의 글자를 16px 아래로 내리지 않는다.** iOS 사파리는 그런 칸에 커서가
  들어가면 읽히도록 화면을 통째로 확대한다. 「할 말 있어요」를 누르면 바로 커서를
  넣어 주므로, 14px로 뒀을 때 **누르는 순간 마을이 확대돼 보였다**
- **실패를 성공처럼 보이게 하지 않는다.** 조용히 고맙다고 하면 방문자는 남겼다고 믿고
  나는 못 받는다 — 그게 제일 나쁘다. 못 받으면 못 받았다고 말한다
- **길다고 버리지 않는다.** 말 1000자 · 이름 40자에서 **자른다.** 길게 쓴 사람의 글을
  통째로 버리는 것보다 낫다
- **봇에게는 받은 척한다.** 사람 눈에 안 보이는 칸(`hp`)이 채워져 있으면 200을 주고
  버린다. 거절하면 봇이 다른 방법을 찾는다
- **도배는 IP당 1분에 3번까지.** KV 카운터 하나로 세고, 창이 지나면 저절로 사라진다
- **남기고 나면 폼을 치운다.** 빈 칸을 다시 내밀면 방금 남긴 것이 안 갔나
  싶어진다. 이때 알림 문구(`#sayNote`)는 **폼 바깥**에 있어야 한다 — 안에 뒀다가
  폼과 함께 사라져 고맙다는 말이 안 뜬 적이 있다
- **폼에 `novalidate`를 둔다.** 브라우저가 제 말풍선("이 입력란을 작성하세요")으로
  먼저 막아 버리면 우리 안내가 뜰 자리가 없다. 빈 칸 검사는 JS가 한다 — 한국어이고,
  창 안 그 자리에 뜨고, 서버가 준 말과 같은 자리를 쓴다
- **KV 키의 꼬리표는 진짜 임의값이어야 한다.** 처음에는 앞머리와 같은 밀리초를
  36진수로 바꿔 붙였는데 그건 아무것도 갈라 주지 못해서, 1밀리초 안에 둘이 들어오면
  **먼저 온 말이 덮여 사라졌다.** 지금은 `crypto.randomUUID()`의 앞 8자다

## 배포

Cloudflare Workers. 빌드 명령 없이 **저장소 루트를 통째로 올린다**
(`wrangler.jsonc`의 `assets.directory: "."`, 배포 명령은 `npx wrangler deploy`).
`main`으로 `worker.js`가 함께 올라가지만 하는 일은 위의 `/api/word` 하나뿐이다.

**게시되는 것은 저장소의 기본 브랜치다.** 다른 브랜치에 올린 작업은 아무리 커밋해도
사이트에 나타나지 않는다 — "고쳤는데 왜 그대로지?" 싶으면 여기부터 확인한다.
`git remote show origin`의 `HEAD branch`가 지금 게시 중인 브랜치다.

### 주소 — dada-town.com

**커스텀 도메인은 대시보드에서 붙였다** (2026-08-24). Cloudflare Registrar에서 산
도메인이라 네임서버를 바꿀 일이 없었다 — 이미 Cloudflare 존이라 Custom Domain으로
바로 붙는다.

```
Workers & Pages → dada-portfolio → Settings → Domains & Routes → Add → Custom Domain
```

DNS 레코드와 인증서는 Cloudflare가 만든다. **`wrangler.jsonc`에 `routes`를 적지
않는다** — 기본 브랜치에 올라가면 Cloudflare가 알아서 배포하는데, 그때 이 파일의
라우트가 진실이 되어 대시보드에서 붙인 것을 덮어쓸 수 있다. 한쪽에서만 관리한다.

**Custom Domain은 주소가 글자까지 똑같아야 받는다.** `dada-town.com`에 붙였다고
`www.dada-town.com`이 따라오지 않아 **따로 한 번 더 붙여야 한다.**

주소를 바꾸면 함께 가는 것이 넷이다. 하나만 고치고 넘어가면 나머지가 예전 주소를
가리킨 채 남는다.

| 어디 | 무엇 |
|---|---|
| `services.json`의 `site.url` | 여기 하나가 `list.html`·`sitemap.xml`·`robots.txt`를 만든다 (`build_list.py`) |
| `index.html`·`game/index.html`·`case/playgrown.html` | `canonical`·`og:url`·`og:image` — 손으로 쓴 세 장이라 각자 박혀 있다 |
| `ga.js`의 `HOSTS` | **여기 없는 주소에서는 통계가 통째로 안 켜진다** |
| `wrangler.jsonc`의 주석 | 어디서 관리하는지를 적어 둔 자리 |

**예전 주소(`dada-portfolio.stupidpoohh.workers.dev`)는 껐다** (2026-08-24) —
같은 자리에서 `workers.dev` 줄을 Disable 했고, Web Analytics의 그 사이트도 지웠다.
`ga.js`의 `HOSTS`에서도 뺐다. 죽은 주소를 목록에 두면 「지금 살아 있는 주소」로
읽히기 때문이다.

### 미리보기 그림 (og:image)

카톡·슬랙에 주소를 붙여 넣으면 뜨는 그림이다. **지도만 걸지 않는다**(2026-08-24) —
그림 한 장으로는 이 사이트가 무엇인지 말하지 못한다. 이름 · 한 줄 소개 · 지도가
한 장에 든 것을 쓴다.

```
_material/OG.png          다원님이 준 원본 (.gitignore — 저장소에 안 둔다)
node tools/cut_og.mjs     → assets/og/home.jpg  1200x900  197KB
```

**원본(1.5MB PNG)을 그대로 걸지 않는 이유**는 og:image가 **남의 서버가 대신 받아
가는 그림**이기 때문이다. 무거우면 미리보기가 늦게 뜨거나 아예 안 뜬다.
JPEG로 다시 담기만 해도 1/7이 된다.

**비율은 원본 그대로 둔다.** 1.91:1로 맞추자고 자르면 잡아 둔 구도에서 위아래가
잘려 나간다. 카톡은 카드 안에 맞춰 넣어 주므로 4:3이어도 괜찮다.

`og:image:width`·`height`를 적어 두면 미리보기를 만드는 쪽이 자리를 먼저 잡을 수
있다. **적은 값이 실제와 다르면 카드 비율이 어긋나므로** 회귀 테스트가 둘을
견준다(「미리보기 그림」) — 이 값들은 화면에 안 보이는 것이라 깨져도 티가 안 난다.

**`og:image`와 `og:url`은 반드시 절대 주소여야 한다.** 상대 경로로 두면 카카오톡·
링크드인 같은 크롤러가 그림을 못 찾아 미리보기가 아예 안 생긴다. 이것도 회귀
테스트가 본다.

### 방문 통계 — 이제 둘이 아니라 하나 반이다

**Cloudflare Web Analytics는 손을 뗐다** (2026-08-24). 도메인이 Cloudflare 존이
되면서 대시보드에 **「Automatic setup」**으로 저절로 올라오고, Cloudflare가 지나가는
HTML에 비콘을 알아서 끼워 넣는다. 그래서 `ga.js`의 `CF_TOKEN`을 비웠다.

> 여기에 「Workers 정적 에셋에는 자동 삽입이 없다, 그건 Pages 전용」이라고 적어
> 뒀던 것은 **틀린 말이었다.** 존이 아니라서 안 됐던 것이지 Workers라서 안 된 것이
> 아니었다. 존이 생기니 그대로 된다.

토큰을 그대로 뒀으면 한 페이지에서 **비콘이 둘** 붙었다. 예전 토큰은 workers.dev
사이트의 것이라 Cloudflare가 호스트를 맞춰 보고 버리므로 숫자가 겹치지는 않지만,
버려질 요청을 방문자마다 하나씩 더 보내는 셈이었다.

**GA4는 그대로 둔다.** 세는 것이 다르기 때문이다 — 「몇 명이 왔나」는 쿠키를 안 심는
Cloudflare 쪽이 정확하고, 「무엇을 눌렀나」(구역을 열었다 · 책을 넘겼다)는 커스텀
이벤트가 있는 GA만 안다. `ga.js`의 `HOSTS`가 GA를 켜는 자리이므로 **거기 없는
주소에서는 GA가 통째로 안 켜진다.**

존이 아닌 주소(`*.workers.dev` 등)에 다시 걸 일이 생기면 `CF_TOKEN`에 토큰만 도로
적으면 된다. 코드는 남겨 뒀다.

### 루트를 통째로 올린다는 것의 함정

에셋 디렉터리가 `.`이라 **저장소에 있는 모든 파일이 업로드 대상**이다. 두 번 데였다.

- **깨진 심볼릭 링크** — 테스트용 `node_modules` 링크가 `git add -A`에 딸려 들어갔다.
  `.gitignore`에 `node_modules/`라고 슬래시를 붙여둔 게 화근이었다. 슬래시가 붙으면
  디렉터리만 걸러 심볼릭 링크는 그냥 통과한다. 지금은 슬래시 없이 `node_modules`.
- **빌드가 만드는 `node_modules`** — `package.json`이 생기자 빌드가 `bun install`을 돌리고
  `npx wrangler deploy`가 wrangler를 저장소 안에 설치했다. 그 안의 `workerd` 바이너리가
  **144MB**라 25MB 제한에 걸려 배포가 통째로 실패했다
  (`Read 2398 files from the assets directory` → `Asset too large`).

그래서 **올리지 않을 것은 `.assetsignore`에 적는다.** 지금은 66개 · 3.1MB만 올라간다.
`wrangler.jsonc`를 둔 것도 같은 이유다 — 이 파일이 없으면 wrangler가 배포할 때마다
설정을 스스로 만들며 자기 자신을 저장소에 설치한다.

무엇이 올라갈지는 `Deployments` 탭의 빌드 로그에서 `Read N files from the assets directory`로
확인한다. 이 숫자가 갑자기 커졌으면 `.assetsignore`가 새는 것이다.

### 캐시 — 데이터와 코드는 짝이 맞아야 한다

**한 번 데였다.** `services.json`만 예전 것이 브라우저 캐시에 남은 채 새 `app.js`를
만났다. 마스코트의 `frames`가 배열에서 객체로 바뀐 뒤라 역할 이름이 CSS와 어긋났고,
세 장이 한꺼번에 뜨면서 그중 **사라진 파일 하나가 404** — 카페 앞에 브라우저가 그리는
**물음표 상자**가 그대로 섰다.

빌드 과정이 없어 파일 이름에 해시를 붙일 수 없으므로, 세 겹으로 막는다.

1. **`_headers`에 `Cache-Control: no-cache`** — 화면을 그리는 데이터와 그것을 읽는 코드
   (`services.json` · `game/data.json` · `app.js` · `guide.js` · `ga.js`)만 해당한다.
   `no-cache`는 「쓰지 마라」가 아니라 **「쓰기 전에 반드시 물어봐라」**다. 바뀐 게 없으면
   304로 끝나므로 값은 거의 안 든다. 그림과 지도는 그대로 오래 캐시된다
2. **`fetch(..., { cache: 'no-cache' })`** — 서버 헤더가 어떤 이유로 적용되지 않아도
   데이터만은 반드시 다시 확인하도록 코드 쪽에서 한 번 더 건다
3. **깨진 그림은 스스로 사라진다** (`pixel()`) — 그래도 어긋나는 날이 오면, 지도에
   물음표가 뜨는 대신 그 그림만 조용히 없어진다. 없는 그림이 깨진 그림보다 낫다

회귀 테스트가 셋 다 지킨다.

「주소 — dada-town.com」으로 옮겼다. 같은 이야기를 두 군데서 읽게 두지 않는다.)*
